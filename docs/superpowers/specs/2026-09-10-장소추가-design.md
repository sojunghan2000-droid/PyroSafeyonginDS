# 장소 추가 기능 설계

## 목표

관리자가 "위치 마스터" 화면에서 PDF 도면을 업로드해 새로운 **장소**(건물/구역 단위,
기존 8개 층과 동급 개념)를 앱 재배포 없이 즉시 추가한다. 추가된 장소는 기존 층과
동일하게 앱 전역(위치마스터 / 시설 관리 / 안전점검 / QR스티커 / 보고서센터 /
대시보드)의 층 선택 목록에 나타나야 한다.

## 현재 상태 (문제)

층 목록이 3곳에 하드코딩된 Python 상수로 흩어져 있다:
- `pages_app/dashboard.py` `LOCATION_FLOORS` (9개, TEMP 포함) — `pages_app/report_center.py`가 임포트해서 재사용
- `pages_app/admin_center.py` `ADMIN_FLOORS` (8개, TEMP 미포함)
- `lib/inspection_dialog.py` `SPOT_FLOORS` (9개, TEMP 포함) — `pages_app/equipment_inventory.py`가 임포트해서 재사용

도면 이미지도 로컬 `assets/floors/{floor}.png` 파일이며, PDF → PNG 변환은
`scripts/convert_floor_pdfs.py`를 개발자가 로컬에서 수동 실행 후 git commit해야
반영된다. `pages_app/dashboard.py`와 `pages_app/admin_center.py`에 각각 별도로
`_floor_image_uri()`(로컬 파일 읽기)가 중복 구현되어 있다.

**제약**: Streamlit Cloud는 로컬 디스크에 쓴 파일이 재배포 시 사라지는 환경이라,
앱에서 업로드한 PDF를 로컬에만 저장하면 다음 배포 때 없어진다. 따라서 새로
추가되는 장소의 이미지는 Supabase Storage에 영구 저장해야 한다.

## 데이터 모델

새 테이블 `floors`:

```sql
create table if not exists floors (
  code text primary key,
  display_name text not null,
  image_path text not null,
  sort_order int not null,
  created_at timestamptz not null default now()
);
```

- `code` — 내부 식별자. 표시명에서 자동 생성(영문/숫자만 추출, 대문자화,
  최대 12자). 한글 표시명이라 추출 결과가 빈 문자열이면 `PLACE1`처럼
  `PLACE{n}` 형태로 폴백. 기존 spot_id 체계(`SPOT-{floor}-NNN`)의 `{floor}`
  자리에 그대로 들어가므로 생성 후 변경하지 않는다.
- `display_name` — 화면에 보이는 이름. 나중에 수정 가능(코드는 불변).
- `image_path` — Storage 버킷 `floor-plans` 내 객체 경로 (`{code}.png`).
- `sort_order` — 기존 9개(PIT~Roof, TEMP)를 0~8로 보고, 신규 장소는 9부터
  등록 순서대로 증가.

마이그레이션 파일: `docs/superpowers/migrations/2026-09-10-floors-table.sql`
(위 CREATE TABLE 문). `supabase_schema.sql`에도 동기화.

Storage: 새 버킷 `floor-plans` 필요 (기존 `action-photos` 버킷과 동일한 정책
패턴 — anon 접근 차단, service_role/인증 클라이언트로 업로드). 버킷 생성은
Supabase 대시보드에서 사용자가 직접 진행 (기존 컨벤션과 동일하게, DDL/버킷
생성은 Claude가 직접 실행 못 함 — 정확한 SQL/절차를 안내).

## 마이그레이션 안전 게이트

기존 `*_supported()` 프로브 함수 컨벤션을 따라 `lib/data.py`에
`floors_table_supported() -> bool` 추가 (`select("code").limit(1)`을
try/except로 감싼 형태). 마이그레이션이 아직 반영 안 된 환경에서는
"+ 장소 추가" 버튼이 비활성화되고 안내 캡션만 표시되어, 앱이 절대 크래시하지
않는다.

## 백엔드 함수 (lib/data.py)

- `_floor_rows()` — `@st.cache_data` 캐시된 `floors` 테이블 전체 조회.
  `floors_table_supported()`가 False면 빈 리스트.
- `CORE_FLOORS = ["PIT", "B2", "B1", "1F", "2F", "3F", "4F", "Roof", "TEMP"]` —
  기존 9개 층, 하드코딩 유지(안 바뀌는 값이라 DB로 옮길 실익 없음).
- `load_all_floors() -> list[str]` — `CORE_FLOORS` + DB 커스텀 장소 code
  (`sort_order` 순). 기존 `LOCATION_FLOORS`/`ADMIN_FLOORS`/`SPOT_FLOORS`를
  전부 대체하는 단일 진입점.
- `floor_display_name(code: str) -> str` — DB 커스텀 장소면 `display_name`,
  `CORE_FLOORS`에 속하면 code 그대로 반환(기존 층은 코드가 곧 표시명).
- `add_floor(display_name: str, pdf_bytes: bytes) -> str` —
  1. `pymupdf`(fitz)로 PDF 1페이지 렌더링 → PNG bytes
     (`scripts/convert_floor_pdfs.py`와 동일하게 `RENDER_DPI = 180`).
  2. `display_name`에서 code 생성, `CORE_FLOORS ∪ 기존 DB code`와 충돌 검사 →
     충돌 시 숫자 접미사(`-2`, `-3`, ...)로 유일성 보장.
  3. `floor-plans` 버킷에 `{code}.png` 업로드.
  4. `floors` 테이블에 행 insert (`sort_order` = 현재 최댓값 + 1, 없으면 9).
  5. `_floor_rows.clear()` 캐시 무효화, code 반환.
  업로드 실패 시 테이블 insert를 하지 않고 예외를 올려 다이얼로그에서
  에러로 표시한다(부분 실패로 이미지만 남는 상태 방지).
- `rename_floor(code: str, new_display_name: str) -> None` — DB 커스텀
  장소만 대상. `code`가 `CORE_FLOORS`에 있으면 `ValueError`.
- `get_floor_image_bytes(code: str) -> bytes | None` — `CORE_FLOORS`면 로컬
  `assets/floors/{code}.png` 읽기, DB 커스텀이면 Storage에서
  `image_path` 다운로드. 두 파일의 중복 `_floor_image_uri()` 구현
  (dashboard.py, admin_center.py)이 이 함수 하나를 감싸는 얇은 wrapper로
  통합된다.

## UI 흐름 (pages_app/admin_center.py)

- `_spot_master_tab()` 헤더 우측, 기존 `"+ 신규 위치 등록"` 버튼 **왼쪽**에
  `"+ 장소 추가"` 버튼 추가 (columns 비율 조정, `head_r`를 2등분).
  `floors_table_supported()`가 False면 버튼을 비활성화하고 "먼저 DB
  마이그레이션이 필요합니다" 캡션 표시.
- 신규 다이얼로그 `_floor_add_dialog()` (`@st.dialog`, 기존 `_spot_define_dialog`
  패턴과 동일한 스타일):
  1. `st.file_uploader("PDF 도면", type=["pdf"])`.
  2. 표시명 `st.text_input` (기본값: 업로드 파일명에서 확장자 제거).
  3. 업로드되면 즉시 pymupdf로 1페이지 렌더링해 **미리보기 이미지**와
     자동 생성될 코드를 화면에 보여준다 (아직 저장 전 — 확정 전 렌더링
     요구사항).
  4. "확정" 버튼 → `data.add_floor()` 호출 → 성공 시 성공 토스트, 다이얼로그
     닫고 `st.rerun()`. 실패 시 `st.error()`로 원인 표시(다이얼로그 유지).
  5. "취소" 버튼.
- DB 커스텀 장소가 1개 이상 있으면, 층 선택 selectbox 아래에 작게
  "표시명 수정" 인라인 편집을 노출(해당 장소 선택 시에만). `CORE_FLOORS`는
  수정 UI를 제공하지 않는다.

## 전역 연동 지점 교체 (5개 파일)

1. `pages_app/dashboard.py` — `LOCATION_FLOORS` 상수 제거,
   `data.load_all_floors()` 호출로 대체. `_floor_image_uri()`는
   `data.get_floor_image_bytes()`를 감싸는 wrapper로 축소.
2. `pages_app/admin_center.py` — `ADMIN_FLOORS` 상수 제거,
   `data.load_all_floors()` 사용. `_floor_image_uri()` 동일하게 축소.
3. `lib/inspection_dialog.py` — `SPOT_FLOORS` 상수 제거,
   `data.load_all_floors()` 사용.
4. `pages_app/equipment_inventory.py` — `SPOT_FLOORS` 대신
   `data.load_all_floors()` 사용. `EQ_FLOORS`는 PRD에 이미 죽은 코드로
   기록된 레거시라 손대지 않는다.
5. `pages_app/report_center.py` — `from pages_app.dashboard import
   LOCATION_FLOORS` 대신 `data.load_all_floors()` 사용.

## 에러 처리

- 업로드 파일이 PDF가 아니거나 파싱 실패 → `st.error`, 저장 안 함.
- 표시명이 비어 있음 → `st.error`.
- code 충돌 → 자동으로 숫자 접미사 부여, 최종 code를 사용자에게 보여줌
  (조용히 덮어쓰지 않음).
- `floor-plans` 버킷이 없거나 업로드 실패 → `st.error`로 버킷 생성 필요
  안내, `floors` 테이블에는 insert하지 않음(반쪽 상태 방지).

## 테스트/검증 계획

- `python -c "import ast; ast.parse(...)"` 문법 체크 (수정되는 6개 파일 전체).
- 헤드리스 스모크: `data.load_all_floors()`가 마이그레이션 전/후 모두
  예외 없이 동작하는지, code 자동 생성/충돌 처리 로직을 실제 값으로 확인.
- 로컬 서버 기동 후 위치마스터 탭에서 실제 PDF 한 장 업로드 → 미리보기 →
  확정 → 5개 연동 지점(층 선택 드롭다운들)에 새 장소가 실제로 나타나는지
  육안 확인.
- 마이그레이션 SQL과 Storage 버킷 생성은 기존 컨벤션대로 사용자가
  Supabase 대시보드/SQL Editor에서 직접 실행 후, `floors_table_supported()`
  로 반영 확인.

## 범위 밖

- 기존 8개 층(PIT~Roof) + TEMP의 삭제·이름변경 — 요청에 없음, 손대지 않음.
- 장소 삭제 기능 — 요청에 없음, 필요 시 별도 논의.
- 한 장소에 여러 페이지/여러 PDF 첨부 — PDF 1페이지만 지원(2페이지 이상이면
  1페이지만 사용, 별도 경고 없음 — 기존 변환 스크립트와 동일 동작).
